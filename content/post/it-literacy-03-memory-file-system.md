# IT 리터러시 3편: 메모리와 파일 시스템은 왜 필요할까?

> 이 글은 IT 리터러시 수업 내용 중 메모리 관리와 파일 시스템을 정리한 글이다.  
> 핵심은 운영체제가 프로그램 실행을 위해 메모리를 어떻게 나누고, 파일을 어떻게 저장장치와 연결해 관리하는지 이해하는 것이다.

---

## 1. 메모리 관리는 프로그램 실행을 위한 공간 관리다

메모리 관리는 프로그램이 잘 실행될 수 있도록 메모리를 할당하고 해제하는 작업이다.

프로그램이 실행되려면 필요한 데이터와 명령어가 메모리에 올라와야 한다.  
하지만 메모리는 무한하지 않기 때문에 운영체제는 여러 프로세스가 사용할 메모리를 효율적으로 나눠줘야 한다.

메모리 관리에서 중요한 질문은 다음과 같다.

```text
어떤 프로세스에게 어느 메모리 공간을 줄 것인가?
사용이 끝난 메모리는 어떻게 회수할 것인가?
부족한 메모리는 어떻게 보완할 것인가?
```

---

## 2. 연속 할당과 불연속 할당

메모리를 할당하는 방식은 크게 연속 할당과 불연속 할당으로 나눌 수 있다.

![연속 할당과 불연속 할당](/img/it-literacy/memory-allocation.svg)

연속 할당은 하나의 프로세스에게 연속된 메모리 공간을 제공하는 방식이다.  
호텔 방으로 비유하면 한 손님에게 연속된 방 번호를 주는 것과 비슷하다.

불연속 할당은 하나의 프로세스가 꼭 연속된 공간을 차지하지 않아도 되는 방식이다.  
즉, 비어 있는 여러 공간에 나누어 배치할 수 있다.

| 방식 | 설명 |
|---|---|
| 연속 할당 | 프로세스가 연속된 메모리 공간을 사용 |
| 불연속 할당 | 프로세스가 여러 위치에 나뉘어 저장될 수 있음 |

---

## 3. 고정 분할 방식과 가변 분할 방식

고정 분할 방식은 메모리를 미리 고정된 크기로 나누고, 각 공간을 프로세스에게 할당하는 방식이다.

예를 들어 방 크기를 모두 같은 크기로 미리 나눠놓고 손님에게 배정하는 방식이다.

장점은 구조가 단순하다는 것이다.  
하지만 프로세스가 실제로 필요한 크기보다 큰 공간을 받으면 사용하지 않는 공간이 생긴다. 이것이 내부 단편화이다.

가변 분할 방식은 프로세스마다 필요한 크기에 맞게 메모리를 할당하는 방식이다.  
내부 단편화는 줄일 수 있지만, 시간이 지나면서 빈 공간이 여기저기 흩어지는 외부 단편화가 발생할 수 있다.

| 방식 | 장점 | 단점 |
|---|---|---|
| 고정 분할 | 관리가 단순함 | 내부 단편화 발생 |
| 가변 분할 | 필요한 만큼 할당 가능 | 외부 단편화 발생 가능 |

---

## 4. 내부 단편화와 외부 단편화

단편화는 메모리 공간이 낭비되는 문제이다.

내부 단편화는 할당받은 공간 내부에 사용하지 않는 공간이 남는 현상이다.

예를 들어 10MB 공간을 할당받았는데 실제로 7MB만 사용한다면, 남은 3MB는 내부에서 낭비된다.

외부 단편화는 전체 빈 공간은 충분하지만, 연속된 큰 공간이 없어 새로운 프로세스를 넣지 못하는 현상이다.

예를 들어 빈 방은 여러 개 있지만 모두 떨어져 있어서 단체 손님을 한 번에 받을 수 없는 상황과 비슷하다.

| 구분 | 설명 |
|---|---|
| 내부 단편화 | 할당된 공간 안에서 남는 공간 발생 |
| 외부 단편화 | 빈 공간은 있지만 연속 공간이 부족 |

일반적으로 외부 단편화가 내부 단편화보다 더 큰 공간 낭비로 이어질 수 있다.

---

## 5. 가상 메모리

가상 메모리는 실제 물리 메모리를 직접 보여주는 대신, 각 프로세스가 독립적인 메모리 공간을 가진 것처럼 보이게 하는 기술이다.

가상 메모리의 장점은 다음과 같다.

1. 모든 프로세스가 고정된 주소를 가진 것처럼 사용할 수 있다.
2. 실제 물리 주소는 운영체제가 관리하므로 리소스 보호가 가능하다.
3. 보조기억장치 일부를 메모리처럼 사용할 수 있다.

즉, 가상 메모리는 프로세스에게는 편리한 주소 공간을 제공하고, 운영체제는 실제 물리 메모리를 효율적으로 관리할 수 있게 해준다.

---

## 6. 페이지와 페이징

가상 메모리는 페이지라는 단위로 관리된다.  
페이지는 가상 주소와 물리 메모리를 연결하는 단위이다.

일반적으로 페이지 크기는 4KB 또는 8KB 정도이다.

![가상 메모리와 페이징](/img/it-literacy/virtual-memory-paging.svg)

페이징은 메모리를 일정한 크기의 페이지 단위로 나누어 관리하는 기법이다.  
이 방식은 가상 주소와 물리 주소를 매핑하는 페이지 테이블을 사용한다.

쉽게 말하면 다음과 같다.

```text
가상 메모리의 Page 1 → 물리 메모리의 Frame 3
가상 메모리의 Page 2 → 현재 디스크에 있음
가상 메모리의 Page 3 → 물리 메모리의 Frame 1
```

운영체제는 페이지 테이블을 보고 가상 주소가 실제 물리 메모리의 어디에 있는지 찾아간다.

---

## 7. 스와핑과 요구 페이징

스와핑은 당장 사용하지 않는 프로세스나 메모리 내용을 잠시 하드디스크로 옮겨두는 방식이다.

과거에는 프로세스 단위로 메모리와 하드디스크를 전환하는 방식이 사용되었다.  
하지만 프로세스 전체를 옮기는 것은 비효율적이고 단편화 문제도 생길 수 있다.

그래서 최근에는 페이지 단위로 필요한 부분만 가져오는 요구 페이징 방식이 중요하다.

요구 페이징은 당장 필요한 페이지만 메모리에 올리고, 필요하지 않은 페이지는 보조기억장치에 둘 수 있는 방식이다.

```text
필요한 페이지 → 메모리에 적재
당장 필요 없는 페이지 → 디스크에 보관
```

이 방식은 실제 물리 메모리를 하드디스크의 캐시처럼 활용하는 관점으로 이해할 수 있다.

---

## 8. 캐시

캐시는 데이터나 값을 미리 복사해두는 임시 저장 공간이다.  
자주 사용하는 데이터를 가까운 곳에 두면 더 빠르게 접근할 수 있다.

예를 들어 매번 책장을 뒤져서 내용을 찾는 것보다, 자주 보는 내용을 손바닥에 적어두면 훨씬 빠르게 볼 수 있다.  
다만 손바닥에는 많은 내용을 적을 수 없기 때문에 필요한 것만 잘 골라 적어야 한다.

컴퓨터에서도 캐시는 빠르지만 용량이 작다.  
그래서 자주 사용할 가능성이 높은 데이터를 미리 올려두는 전략이 중요하다.

---

## 9. 페이징과 세그멘테이션

페이징은 메모리를 일정한 크기로 자르는 방식이다.  
구조가 단순하고 관리하기 쉽지만, 일정한 크기로 자르기 때문에 내부 단편화가 발생할 수 있다.

세그멘테이션은 논리적으로 같은 역할을 하는 부분끼리 나누는 방식이다.  
예를 들어 코드, 데이터, 스택처럼 의미 있는 단위로 나누는 방식이다.

| 방식 | 기준 | 장점 | 단점 |
|---|---|---|---|
| 페이징 | 일정한 크기 | 관리가 단순함 | 내부 단편화 발생 |
| 세그멘테이션 | 논리적 단위 | 의미 있는 단위로 관리 가능 | 외부 단편화 발생 가능 |

세그멘테이션은 중요한 부분과 아닌 부분을 분리하여 저장할 수 있어 효율적이다.  
하지만 길이가 다르게 잘리기 때문에 외부 단편화가 발생할 수 있다.

페이징과 세그멘테이션을 함께 사용하면 세그멘테이션의 장점을 살리면서 외부 단편화를 줄일 수 있다.  
다만 테이블을 두 번 거쳐야 하므로 조금 느려질 수 있다.

## 10. 파일 시스템은 파일을 쉽게 접근하도록 관리하는 체제다

파일은 컴퓨터에서 정보를 담는 논리적인 저장 단위이다.  
파일 시스템은 이러한 파일들을 쉽게 접근할 수 있도록 관리하는 체제이다.

파일 시스템이 없다면 사용자는 저장장치의 물리적 위치를 직접 알아야 할 것이다.  
하지만 파일 시스템 덕분에 우리는 경로와 파일명만으로 파일에 접근할 수 있다.

```text
C:/Users/user/document.txt
/home/user/data.csv
```

파일 시스템은 디스크, 네트워크, 특수 용도의 파일 시스템 등으로 나뉠 수 있다.

## 11. HDD와 SSD

저장장치는 대표적으로 HDD와 SSD가 있다.

HDD는 플래터와 헤드로 이루어져 있다.  
플래터가 회전하고, 헤드가 정보를 읽고 쓰는 방식이다.

HDD는 트랙과 섹터로 구성된다.

- 트랙: 플래터 위의 띠 모양 영역
- 섹터: 하드 드라이브의 최소 기억 단위

SSD는 HDD와 다르게 물리적인 기계 장치 없이 전기 장치로만 구성된다.  
모터와 같은 기계 장치가 없기 때문에 일반적으로 HDD보다 빠르다.

| 구분 | HDD | SSD |
|---|---|---|
| 구조 | 플래터와 헤드 | 전기적 저장장치 |
| 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 특징 | 물리적 회전 구조 | 기계적 움직임 없음 |

## 12. 마운트란 무엇인가?

마운트는 물리적인 저장장치를 특정 디렉터리에 연결하는 것이다.

![파일 시스템, 저장장치, 마운트](/img/it-literacy/file-system-storage.svg)

새로운 물리 장치를 사용하려면 운영체제가 그 장치를 인식하고 접근할 수 있어야 한다.  
이때 장치를 특정 디렉터리에 연결하는 작업이 마운트이다.

Linux에서는 다음과 같은 형태로 마운트 명령을 사용할 수 있다.

```bash
sudo mount [옵션] [장치] [디렉터리]
```

- 장치: 연결할 저장장치 이름
- 디렉터리: 해당 장치를 연결할 위치
- 옵션: 파일 시스템 유형 등 추가 설정

일부 운영체제에서는 USB나 외장하드를 연결하면 자동으로 마운트가 실행된다.  
하지만 서버나 Linux 환경에서는 직접 마운트 개념을 이해하고 있어야 할 때가 있다.

## 13. 정리하며

이번 글에서는 메모리 관리와 파일 시스템을 정리했다.

핵심은 다음과 같다.

| 개념 | 정리 |
|---|---|
| 메모리 관리 | 프로그램 실행을 위해 메모리를 할당하고 해제하는 작업 |
| 연속 할당 | 연속된 메모리 공간을 할당하는 방식 |
| 불연속 할당 | 여러 위치에 나누어 저장할 수 있는 방식 |
| 내부 단편화 | 할당된 공간 안에서 낭비가 생기는 문제 |
| 외부 단편화 | 빈 공간은 있지만 연속 공간이 부족한 문제 |
| 가상 메모리 | 각 프로세스가 독립된 메모리 공간을 가진 것처럼 보이게 하는 기술 |
| 페이징 | 메모리를 일정한 페이지 단위로 관리하는 방식 |
| 세그멘테이션 | 논리적 의미 단위로 메모리를 나누는 방식 |
| 파일 시스템 | 파일을 쉽게 접근할 수 있도록 관리하는 체제 |
| 마운트 | 저장장치를 특정 디렉터리에 연결하는 작업 |

메모리와 파일 시스템은 사용자가 직접 보기 어렵지만, 프로그램 실행과 데이터 저장의 기반이다.  
운영체제는 메모리를 효율적으로 나누고, 파일 시스템을 통해 저장장치의 복잡한 구조를 사용자가 쉽게 다룰 수 있게 해준다.

결국 메모리 관리는 “실행 중인 프로그램의 공간 관리”이고, 파일 시스템은 “저장된 데이터의 접근 관리”라고 정리할 수 있다.
