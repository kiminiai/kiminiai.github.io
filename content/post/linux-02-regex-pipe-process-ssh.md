## 1. 정규 표현식이란?

정규 표현식은 특정한 규칙을 가진 문자열을 찾기 위한 표현 방식이다.  
영어로는 Regular Expression이라고 하며, 줄여서 Regex라고도 한다.

예를 들어 다음과 같은 상황을 생각해볼 수 있다.

- 파일에서 특정 단어가 들어간 줄을 찾고 싶다.
- 숫자로 시작하는 문자열만 찾고 싶다.
- 전화번호 형식과 비슷한 문자열을 찾고 싶다.
- 이메일 형식처럼 보이는 문자열을 찾고 싶다.

이런 경우 단순 문자열 검색만으로는 부족할 수 있다.  
정규 표현식은 “문자열의 패턴”을 기준으로 원하는 값을 찾을 수 있게 해준다.

---

## 2. 자주 사용하는 정규 표현식 메타 문자

정규 표현식에는 특별한 의미를 가진 문자가 있다.  
이런 문자를 메타 문자라고 한다.

| 메타 문자 | 의미 |
|---|---|
| `^` | 문자열의 시작 |
| `$` | 문자열의 끝 |
| `.` | 임의의 문자 하나 |
| `\s` | 공백 문자 |
| `\S` | 공백 문자가 아닌 것 |
| `\d` | 숫자 |
| `\D` | 숫자가 아닌 것 |
| `\w` | 알파벳, 숫자, 언더스코어 |
| `\W` | `\w`에 해당하지 않는 문자 |
| `\n` | 개행 문자 |
| `\t` | 탭 문자 |
| `\` | 메타 문자를 일반 문자로 사용 |

예를 들어 `^010`은 `010`으로 시작하는 문자열을 의미한다.

```regex
^010
```

`\d`는 숫자를 의미한다.

```regex
\d
```

## 3. 선택 패턴과 수량 한정자

대괄호 `[]`는 여러 문자 중 하나에 매칭될 때 사용한다.

| 패턴 | 의미 |
|---|---|
| `[0-9]` | 0부터 9까지 숫자 하나 |
| `[A-Z]` | A부터 Z까지 대문자 하나 |
| `[^0-9]` | 숫자가 아닌 문자 하나 |

여기서 `[]` 안에 있는 `^`는 not의 의미를 가진다.  
즉, `[^0-9]`는 숫자가 아닌 문자를 의미한다.

수량 한정자는 앞의 패턴이 몇 번 반복되는지를 나타낸다.

| 수량자 | 의미 |
|---|---|
| `?` | 0개 또는 1개 |
| `*` | 0개 이상 |
| `+` | 1개 이상 |
| `{n}` | n개 |
| `{n,m}` | n개 이상, m개 이하 |
| `{n,}` | n개 이상 |

예를 들어 숫자 4개를 의미하려면 다음과 같이 쓸 수 있다.

```regex
\d{4}
```

그룹을 만들 때는 괄호 `()`를 사용한다.

```regex
(\D?\d{4}){2}
```

이 패턴은 숫자가 아닌 문자가 있을 수도 있고 없을 수도 있는 형태와 숫자 4개가 묶인 그룹이 2번 반복되는 형태로 볼 수 있다.

## 4. `grep`: 파일에서 원하는 문자열 찾기

`grep`은 파일 안에서 특정 패턴이나 문자열을 찾고, 그 패턴이 포함된 행을 출력하는 명령어이다.

기본 사용법은 다음과 같다.

```bash
grep elice hello.txt
```

이 명령어는 `hello.txt` 파일에서 `elice`라는 문자열이 들어간 모든 행을 출력한다.

문자열이 들어간 행의 개수만 보고 싶다면 `-c` 옵션을 사용한다.

```bash
grep -c elice hello.txt
```

정리하면 다음과 같다.

| 명령어 | 의미 |
|---|---|
| `grep elice hello.txt` | `elice`가 포함된 행 출력 |
| `grep -c elice hello.txt` | `elice`가 포함된 행의 개수 출력 |

`grep`은 로그 분석, 데이터 전처리, 서버 문제 확인에서 매우 자주 사용된다.  
예를 들어 에러 로그에서 `ERROR`가 들어간 줄만 찾을 수 있다.

```bash
grep ERROR app.log
```

## 5. 리다이렉션: 출력 결과를 파일로 보내기

리눅스 명령어의 결과는 기본적으로 화면에 출력된다.  
하지만 그 결과를 파일에 저장하고 싶을 때가 있다.

이때 사용하는 것이 리다이렉션이다.

| 기호 | 의미 |
|---|---|
| `>` | 출력 결과를 파일에 저장. 기존 내용은 덮어씀 |
| `>>` | 출력 결과를 파일 끝에 추가 |
| `<` | 파일 내용을 명령어의 입력으로 전달 |

예를 들어 현재 디렉토리 목록을 `output.txt`에 저장하려면 다음과 같이 입력한다.

```bash
ls > output.txt
```

주의할 점은 `>`는 기존 파일 내용이 있다면 지우고 새로 쓴다는 것이다.  
기존 내용 뒤에 이어서 작성하고 싶다면 `>>`를 사용해야 한다.

```bash
ls >> output.txt
```

입력 방향을 바꾸는 `<`도 사용할 수 있다.

```bash
cat < hello.txt > elice.txt
```

이 명령어는 `hello.txt`의 내용을 `cat` 명령어의 입력으로 전달하고, 그 출력 결과를 `elice.txt`에 저장하는 흐름으로 이해할 수 있다.

## 6. Pipe: 명령어와 명령어를 연결하기

파이프는 앞 명령어의 출력 결과를 뒤 명령어의 입력으로 넘기는 기능이다.  
기호는 `|`를 사용한다.

![Pipe와 Redirection 흐름](/img/linux-basics/pipe-redirection.svg)

예를 들어 다음 명령어를 보자.

```bash
head a.txt | grep [0-9]
```

이 명령어는 다음 순서로 동작한다.

1. `head a.txt`가 `a.txt`의 첫 10줄을 출력한다.
2. 출력된 결과가 파이프 `|`를 통해 `grep`으로 전달된다.
3. `grep [0-9]`가 숫자가 포함된 행만 출력한다.

즉, 파이프를 사용하면 여러 명령어를 조합해서 더 복잡한 작업을 할 수 있다.

---

## 7. Pipe와 Redirection을 함께 사용하기

파이프와 리다이렉션은 함께 사용할 수 있다.

```bash
head a.txt | grep [0-9] > result.txt
```

이 명령어는 다음 흐름으로 동작한다.

1. `head a.txt`로 파일의 첫 10줄을 가져온다.
2. 그 결과를 `grep [0-9]`로 넘긴다.
3. 숫자가 포함된 행만 필터링한다.
4. 최종 결과를 `result.txt`에 저장한다.

다른 예시도 볼 수 있다.

```bash
ls | grep user01 > output.txt
```

이 명령어는 현재 디렉토리 목록 중 `user01`이라는 이름이 포함된 결과만 `output.txt`에 저장한다.

이처럼 리눅스에서는 작은 명령어들을 조합해서 원하는 결과를 만들어낸다.  
이 방식이 CLI의 강력한 장점이다.

## 8. Mount: 저장 장치를 디렉토리에 연결하기

`mount`는 물리적인 저장 장치를 특정 디렉토리에 연결하는 작업이다.

윈도우에서는 USB나 외장하드를 연결하면 자동으로 드라이브가 잡히는 경우가 많다.  
이런 자동 연결 방식을 PnP, 즉 Plug and Play라고 한다.

반면 리눅스에서는 환경에 따라 저장 장치를 직접 마운트해야 사용할 수 있다.

기본 형식은 다음과 같다.

```bash
mount [option] [device] [directory]
```

예를 들어 특정 장치를 `/mnt/usb`에 연결하는 식으로 사용할 수 있다.

```bash
sudo mount /dev/sdb1 /mnt/usb
```

마운트된 디스크 정보를 확인할 때는 `df` 명령어를 사용할 수 있다.

```bash
df
```

파일 시스템 용량을 보기 쉽게 확인하려면 보통 `-h` 옵션을 함께 사용한다.

```bash
df -h
```

정리하면 다음과 같다.

| 명령어 | 의미 |
|---|---|
| `mount` | 저장 장치를 디렉토리에 연결 |
| `df` | 현재 마운트된 디스크 정보 출력 |
| `df -h` | 사람이 읽기 쉬운 단위로 디스크 정보 출력 |

## 9. 프로세스란 무엇인가?

프로세스는 실행 중인 프로그램이다.  
프로그램은 디스크에 저장된 명령어들의 모음이고, 이 프로그램이 실제로 실행되면 프로세스가 된다.

리눅스에서 프로세스는 다음 특징을 가진다.

- 모든 프로그램은 실행될 때 하나 이상의 프로세스를 가진다.
- 여러 프로세스가 병행적으로 실행될 수 있다.
- 부모 프로세스와 자식 프로세스 관계가 있다.
- 커널에 의해 관리된다.
- 모든 프로세스에는 소유자가 있다.
- 각 프로세스는 고유한 PID를 가진다.

PID는 Process ID의 줄임말이다.  
즉, 프로세스를 구분하기 위한 고유 번호이다.

프로세스 목록을 확인할 때는 `ps` 명령어를 사용한다.

```bash
ps
```

전체 프로세스를 더 자세히 보고 싶다면 다음과 같이 사용할 수 있다.

```bash
ps aux
```

프로세스를 종료할 때는 `kill` 명령어를 사용한다.

```bash
kill [PID]
```

자주 사용하는 시그널은 다음과 같다.

| 명령어 | 의미 |
|---|---|
| `kill -1 PID` | 프로세스 재실행 요청 |
| `kill -9 PID` | 강제 종료 |
| `kill -15 PID` | 정상 종료 요청 |

일반적으로는 `kill -15`가 정상 종료 요청이고, `kill -9`는 강제 종료이다.  
따라서 무조건 `kill -9`부터 쓰기보다는 정상 종료가 가능한지 먼저 확인하는 것이 좋다.

## 10. Process, Job, SSH의 관계

프로세스와 Job은 비슷해 보이지만 완전히 같은 개념은 아니다.

![프로세스, Job, SSH 관계](/img/linux-basics/process-job-ssh.svg)

프로세스는 운영체제가 관리하는 실행 단위이다.  
반면 Job은 터미널에서 실행한 작업을 의미한다.

예를 들어 다음처럼 명령어 뒤에 `&`를 붙이면 백그라운드 작업으로 실행된다.

```bash
python app.py &
```

이렇게 실행한 작업은 `jobs` 명령어로 확인할 수 있다.

```bash
jobs
```

중요한 차이는 다음과 같다.

| 구분 | 의미 |
|---|---|
| Process | 운영체제가 관리하는 실행 중인 프로그램 |
| Job | 현재 터미널에서 실행한 작업 |
| PID | 프로세스를 식별하는 번호 |

Job은 터미널 단위로 관리된다.  
따라서 터미널을 종료하면 해당 터미널에 연결된 Job도 함께 종료될 수 있다.

## 11. 예약 작업: at과 crontab

리눅스에서는 명령어를 특정 시간에 실행하도록 예약할 수 있다.

대표적인 명령어는 `at`과 `crontab`이다.

| 명령어 | 의미 |
|---|---|
| `at` | 지정된 시간에 1회 실행 |
| `crontab` | 지정된 시간 규칙에 따라 반복 실행 |

`at`은 한 번만 실행되는 작업에 적합하다.  
예를 들어 오늘 밤 11시에 어떤 명령을 한 번 실행하고 싶을 때 사용할 수 있다.

반면 `crontab`은 반복 작업에 적합하다.  
예를 들어 매일 새벽 3시에 로그를 백업하거나, 매주 월요일에 특정 스크립트를 실행하는 작업에 사용한다.

정리하면 다음과 같다.

```text
at       → 한 번 실행
crontab  → 반복 실행
```

## 12. SSH란 무엇인가?

SSH는 Secure Shell의 줄임말이다.  
네트워크를 통해 다른 컴퓨터에 접속하고, 그 컴퓨터에서 명령어를 실행할 수 있게 해주는 프로토콜이다.

예를 들어 원격 서버에 접속할 때 다음과 같이 사용할 수 있다.

```bash
ssh user@server_ip
```

SSH를 사용하면 내 컴퓨터에서 원격 리눅스 서버에 접속해 명령어를 실행할 수 있다.  
데이터 분석 환경에서도 클라우드 서버나 GPU 서버에 접속할 때 SSH를 자주 사용한다.

---

## 13. SSH와 Telnet의 차이

Telnet도 네트워크를 통해 다른 컴퓨터에 접속하고 명령어를 실행할 수 있게 해주는 프로토콜이다.  
하지만 Telnet은 보안적으로 문제가 크다.

가장 큰 차이는 암호화 여부이다.

| 구분 | SSH | Telnet |
|---|---|---|
| 원격 접속 | 가능 | 가능 |
| 명령 실행 | 가능 | 가능 |
| 암호화 | 지원 | 기본적으로 암호화 없음 |
| 보안성 | 높음 | 낮음 |

Telnet은 패킷 데이터가 암호화되어 있지 않기 때문에 비밀번호 같은 민감한 정보가 노출될 위험이 있다.  
반면 SSH는 데이터를 암호화해서 전송한다.

따라서 실제 원격 접속에서는 Telnet보다 SSH를 사용하는 것이 일반적이다.

우분투에서는 `openssh` 패키지를 통해 SSH 서버를 구동할 수 있다.

## 14. 이 글에서 정리한 명령어 요약

| 분류 | 명령어/기호 | 의미 |
|---|---|---|
| 문자열 검색 | `grep` | 파일에서 특정 문자열 또는 패턴 검색 |
| 개수 출력 | `grep -c` | 패턴이 포함된 행의 수 출력 |
| 출력 저장 | `>` | 기존 내용을 덮어쓰며 저장 |
| 출력 추가 | `>>` | 기존 내용 뒤에 이어서 저장 |
| 입력 변경 | `<` | 파일을 명령어 입력으로 전달 |
| 명령 연결 | `|` | 앞 명령의 출력을 뒤 명령의 입력으로 전달 |
| 디스크 확인 | `df`, `df -h` | 마운트된 디스크 정보 확인 |
| 저장 장치 연결 | `mount` | 장치를 디렉토리에 연결 |
| 프로세스 확인 | `ps`, `ps aux` | 프로세스 목록 확인 |
| 프로세스 종료 | `kill` | PID 기준으로 프로세스 종료 |
| Job 확인 | `jobs` | 현재 터미널의 백그라운드 작업 확인 |
| 1회 예약 | `at` | 지정 시간에 한 번 실행 |
| 반복 예약 | `crontab` | 지정 시간 규칙에 따라 반복 실행 |
| 원격 접속 | `ssh` | 원격 컴퓨터에 안전하게 접속 |

## 15. 정리하며 배운 점

이번 글에서는 리눅스 명령어 중에서도 실제 작업 흐름을 만드는 데 중요한 개념들을 정리했다.

`grep`은 파일에서 원하는 문자열을 찾는 명령어이다.  
정규 표현식을 함께 사용하면 단순 문자열뿐 아니라 특정 패턴을 가진 문자열도 찾을 수 있다.

리다이렉션은 명령어의 출력 방향을 바꾸는 기능이다.  
화면에 출력되는 결과를 파일에 저장하거나, 파일을 명령어의 입력으로 전달할 수 있다.

파이프는 여러 명령어를 연결하는 기능이다.  
앞 명령어의 출력 결과를 뒤 명령어의 입력으로 넘겨서 더 복잡한 작업을 만들 수 있다.

프로세스와 Job은 실행 중인 작업을 이해하는 데 중요하다.  
프로세스는 운영체제가 관리하는 실행 단위이고, Job은 터미널에서 실행한 작업 단위로 볼 수 있다.

마지막으로 SSH는 원격 리눅스 서버에 접속하기 위한 핵심 도구이다.  
서버, 클라우드, 도커, 데이터 분석 환경을 다루기 위해서는 SSH의 개념을 반드시 알고 있어야 한다.

리눅스 명령어는 하나씩 외우는 것보다, 입력과 출력의 흐름을 이해하는 것이 중요하다.

```text
명령어 실행 → 결과 출력 → grep으로 필터링 → pipe로 연결 → redirection으로 저장
```

이 흐름을 이해하면 리눅스 CLI가 단순한 명령어 암기가 아니라, 작은 도구들을 조합해서 작업을 자동화하는 방식이라는 것을 알 수 있다.
