# IT 리터러시 2편: 운영체제는 프로그램을 어떻게 실행할까?

> 이 글은 IT 리터러시 수업 내용 중 운영체제, 프로세스, 스레드, 스케줄링 개념을 정리한 글이다.  
> 핵심은 “운영체제는 하드웨어 자원을 관리하고, 프로그램이 실행될 수 있도록 돕는 관리자”라는 관점으로 이해하는 것이다.

---

## 1. 운영체제는 하드웨어와 프로그램 사이의 관리자다

운영체제는 하드웨어를 포함한 시스템 리소스를 제어하고, 프로그램을 실행해주는 시스템 소프트웨어이다.

우리는 프로그램을 실행할 때 CPU, 메모리, 저장장치, 네트워크 같은 자원을 직접 제어하지 않는다.  
그 사이에서 운영체제가 자원을 관리해준다.

예를 들어 사용자가 프로그램을 실행하면 운영체제는 다음과 같은 일을 한다.

- 프로그램을 메모리에 올린다.
- CPU를 사용할 순서를 정한다.
- 파일을 읽고 쓸 수 있게 해준다.
- 네트워크 통신을 가능하게 한다.
- 여러 프로그램이 서로의 자원을 침범하지 못하게 한다.

운영체제는 단순히 화면을 제공하는 프로그램이 아니라, 컴퓨터 전체 자원을 관리하는 핵심 시스템이다.

---

## 2. 시스템 리소스란 무엇인가?

리소스는 어떤 목적에 이용할 수 있는 자원을 의미한다.  
컴퓨터에서 시스템 리소스는 프로그램 실행에 필요한 하드웨어와 소프트웨어 자원을 말한다.

대표적인 시스템 리소스는 다음과 같다.

| 리소스 | 역할 |
|---|---|
| CPU | 명령어 처리 |
| 메모리 | 실행 중인 데이터와 명령어 저장 |
| 보조기억장치 | 파일과 프로그램을 장기 저장 |
| 네트워크 | 다른 컴퓨터와 통신 |
| 입출력 장치 | 키보드, 마우스, 모니터 등 |

각 응용 프로그램은 운영체제로부터 필요한 리소스를 할당받는다.  
그리고 다른 프로그램의 리소스를 마음대로 사용할 수 없다.

이 구조 덕분에 여러 프로그램이 동시에 실행되어도 서로의 메모리나 파일을 함부로 침범하지 않게 된다.

---

## 3. 운영체제의 주요 기능

운영체제의 주요 기능은 다음과 같이 정리할 수 있다.

| 기능 | 설명 |
|---|---|
| 프로세스 관리 | 실행 중인 프로그램을 관리한다 |
| 메모리 관리 | 프로그램이 사용할 메모리를 할당하고 회수한다 |
| 파일 시스템 관리 | 파일을 읽고 쓸 수 있게 관리한다 |
| 네트워크 관리 | 프로토콜과 포트를 관리해 통신을 지원한다 |
| 입출력 장치 관리 | 키보드, 마우스, 모니터 등 장치를 제어한다 |

특히 개발자 입장에서는 운영체제가 네트워크, 파일, 메모리, 프로세스를 관리한다는 사실을 이해하는 것이 중요하다.  
코드가 실행될 때 실제로는 운영체제가 많은 부분을 대신 처리하고 있기 때문이다.

---

## 4. 운영체제 종류

대표적인 운영체제는 다음과 같다.

| 운영체제 | 특징 |
|---|---|
| Windows | 일반 사용자와 사무 환경에서 많이 사용 |
| macOS | Unix 기반 운영체제, 개발 환경에 적합 |
| Linux | 서버와 개발 환경에서 많이 사용, 무료 및 오픈소스 기반 |
| Android | Linux 기반 모바일 운영체제 |
| iOS | Apple 모바일 운영체제 |

특히 Linux는 서버 환경에서 많이 사용된다.  
웹 서비스, 데이터베이스 서버, 클라우드 서버 등 많은 인프라가 Linux 기반으로 동작한다.

---

## 5. 컨테이너화와 Docker

컨테이너화는 프로그램 실행에 필요한 환경과 패키지를 하나로 묶는 기술이다.  
대표적인 도구가 Docker이다.

개발을 하다 보면 이런 문제가 생길 수 있다.

```text
내 컴퓨터에서는 잘 되는데 서버에서는 안 된다.
```

이유는 Python 버전, 라이브러리 버전, 운영체제 환경, 환경 변수 등이 다를 수 있기 때문이다.  
Docker는 실행 환경을 컨테이너로 묶어 이런 차이를 줄여준다.

즉, 컨테이너화는 “프로그램이 실행될 환경까지 함께 포장하는 방식”으로 이해할 수 있다.

---

## 6. 프로그램과 프로세스

프로그램은 특정 작업을 수행하는 명령어들의 모음이다.  
아직 실행되지 않은 파일 상태라고 볼 수 있다.

반면 프로세스는 실행 중인 프로그램이다.

![프로그램, 프로세스, 스레드](/img/it-literacy/program-process-thread.svg)

예를 들어 크롬 브라우저 설치 파일이나 실행 파일 자체는 프로그램이다.  
그 프로그램을 실행하면 운영체제는 메모리를 할당하고, CPU 사용 순서를 관리한다. 이때 실행 중인 상태가 프로세스이다.

```text
프로그램 + 실행 = 프로세스
```

---

## 7. 스레드는 프로세스 안의 실행 흐름이다

스레드는 프로세스 안에서 실행되는 흐름 단위이다.  
하나의 프로세스에는 하나 이상의 스레드가 존재할 수 있다.

프로세스와 스레드의 차이는 메모리 관점에서 이해하면 좋다.

| 구분 | 특징 |
|---|---|
| 프로세스 | 독립적인 메모리를 할당받는다 |
| 스레드 | 같은 프로세스 안의 메모리를 공유한다 |

스레드는 같은 프로세스의 자원을 공유하기 때문에 프로세스를 새로 만드는 것보다 상대적으로 가볍고 빠르게 작업을 처리할 수 있다.

하지만 자원을 공유하기 때문에 동시에 같은 데이터를 수정할 때 문제가 생길 수도 있다.  
그래서 멀티스레드 환경에서는 동기화가 중요하다.

---

## 8. 프로세스 메모리 구조

프로세스는 실행될 때 메모리 안에서 여러 영역으로 나뉘어 관리된다.

![프로세스 메모리 구조](/img/it-literacy/process-memory.svg)

대표적인 영역은 다음과 같다.

| 영역 | 설명 |
|---|---|
| Code 영역 | CPU가 실행할 명령어 저장 |
| Data 영역 | 전역 변수, 정적 변수 저장 |
| Heap 영역 | 동적 메모리 할당에 사용 |
| Stack 영역 | 함수 호출, 지역 변수, 매개변수 저장 |

Code와 Data 영역은 상대적으로 정적인 성격이 강하다.  
반면 Heap과 Stack은 프로그램 실행 중 계속 변하는 동적인 성격이 강하다.

---

## 9. 정적 할당과 동적 할당

정적 할당은 실행 전에 미리 메모리를 할당하는 방식이다.  
할당받을 크기가 미리 정해져 있기 때문에 상대적으로 빠르다.

동적 할당은 실행 도중 필요한 만큼 메모리를 할당하는 방식이다.  
상황에 따라 크기가 변할 수 있기 때문에 유연하지만, 관리가 어렵고 메모리 누수가 발생할 수 있다.

| 구분 | 설명 | 특징 |
|---|---|---|
| 정적 할당 | 실행 전 메모리 크기 결정 | 빠르지만 유연성이 낮음 |
| 동적 할당 | 실행 중 메모리 할당 | 유연하지만 관리 필요 |

Heap 영역은 동적 메모리 할당을 위해 사용되는 대표적인 영역이다.  
관리를 잘못하면 사용하지 않는 메모리가 계속 남는 메모리 누수가 발생할 수 있다.

---

## 10. 프로세스 상태

프로세스는 실행되는 동안 여러 상태를 거친다.

![프로세스 상태 흐름](/img/it-literacy/process-state.svg)

| 상태 | 설명 |
|---|---|
| 생성 | 프로세스가 만들어지는 단계 |
| 준비 | CPU를 기다리는 상태 |
| 실행 | CPU를 할당받아 명령어를 처리하는 상태 |
| 대기 | 입출력 등 특정 이벤트를 기다리는 상태 |
| 종료 | 모든 명령어 수행이 끝난 상태 |

중요한 점은 프로세스가 계속 실행 상태에만 머무르지 않는다는 것이다.  
운영체제는 여러 프로세스가 공평하게 CPU를 사용할 수 있도록 상태를 계속 바꿔가며 관리한다.

---

## 11. 멀티 프로세싱과 멀티 스레드

멀티 프로세싱은 여러 개의 프로세스를 돌아가면서 조금씩 처리하는 방식이다.

멀티 스레드는 한 프로세스 안에서 여러 스레드가 자원을 공유하며 여러 작업을 처리하는 방식이다.

| 구분 | 설명 | 특징 |
|---|---|---|
| 멀티 프로세싱 | 여러 프로세스를 처리 | 안정적이지만 자원 사용이 큼 |
| 멀티 스레드 | 한 프로세스 안의 여러 실행 흐름 | 빠르지만 공유 자원 관리 필요 |

멀티 스레드는 프로세스 생성과 리소스 할당 과정이 상대적으로 적기 때문에 빠르게 처리할 수 있다.  
하지만 같은 메모리를 공유하므로 데이터 충돌 문제가 생기지 않도록 주의해야 한다.

---

## 12. 프로세스 간 통신

프로세스는 각각 독립적인 메모리를 가진다.  
그래서 서로 데이터를 주고받으려면 운영체제가 허용하는 방식 안에서 통신해야 한다.

대표적인 프로세스 간 통신 방식은 다음과 같다.

| 방식 | 설명 |
|---|---|
| 메시지 큐 | 공용 우편함에 데이터를 넣고 꺼내는 방식 |
| 공유 메모리 | 여러 프로세스가 일부 메모리를 함께 사용하는 방식 |
| 소켓 | 네트워크 통신 방식으로 데이터를 주고받는 방식 |

프로세스 간 통신은 운영체제가 관리하는 안전한 통로를 통해 데이터를 주고받는 방법이라고 이해하면 된다.

---

## 13. 프로세스 스케줄링

프로세스 스케줄링은 운영체제가 어떤 프로세스에 CPU를 줄지 결정하는 과정이다.

목적은 크게 두 가지이다.

1. 대기 시간을 가능한 줄인다.
2. 여러 프로세스를 가능한 공평하게 처리한다.

대표적인 스케줄링 방식은 다음과 같다.

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| 선입선처리 | 먼저 도착한 순서대로 처리 | 구현이 간단함 | 긴 작업이 앞에 있으면 뒤 작업이 오래 기다림 |
| 최단 작업 우선 | 실행 시간이 짧은 작업부터 처리 | 평균 대기시간 감소 | 긴 작업이 계속 밀릴 수 있음 |
| 라운드 로빈 | 일정 시간마다 다음 작업으로 전환 | 응답 시간이 짧음 | 전환이 너무 많으면 오버헤드 발생 |

운영체제는 이런 방식들을 활용해 여러 프로세스가 CPU를 사용할 순서를 조정한다.

---

## 14. 교착상태와 기아상태

교착상태는 프로세스들이 서로 상대방의 작업이 끝나기만을 기다리고 있는 상태이다.  
결과적으로 아무 작업도 완료되지 않는다.

기아상태는 특정 프로세스의 우선순위가 낮아서 원하는 자원을 계속 받지 못하는 상태이다.

![교착상태와 기아상태](/img/it-literacy/deadlock-starvation.svg)

교착상태가 발생하기 위한 대표 조건은 다음과 같다.

| 조건 | 설명 |
|---|---|
| 상호배제 | 자원을 동시에 둘 이상이 사용할 수 없음 |
| 점유대기 | 자원을 가진 상태에서 다른 자원을 기다림 |
| 비선점 | 다른 프로세스가 자원을 강제로 빼앗을 수 없음 |
| 순환대기 | 각 프로세스가 순환적으로 다음 자원을 기다림 |

교착상태는 위 조건 중 하나라도 막으면 예방할 수 있다.  
하지만 실제 시스템에서 교착상태를 완벽히 막는 것은 쉽지 않다.

기아상태는 우선순위를 계속 조정하거나, 오래 기다린 프로세스의 우선순위를 높이는 방식으로 완화할 수 있다.

---

## 15. 정리하며

이번 글에서는 운영체제가 프로그램을 어떻게 실행하고 관리하는지 정리했다.

핵심은 다음과 같다.

| 개념 | 정리 |
|---|---|
| 운영체제 | 하드웨어 자원을 관리하고 프로그램 실행을 돕는 시스템 소프트웨어 |
| 프로그램 | 실행 전 명령어들의 모음 |
| 프로세스 | 실행 중인 프로그램 |
| 스레드 | 프로세스 안의 실행 흐름 |
| 스케줄링 | CPU 사용 순서를 정하는 작업 |
| 교착상태 | 서로 자원을 기다려 아무것도 끝나지 않는 상태 |
| 기아상태 | 우선순위가 낮아 자원을 계속 받지 못하는 상태 |

운영체제는 사용자가 직접 보기 어렵지만, 모든 프로그램 실행의 기반이다.  
개발자가 코드를 작성하면 그 코드는 결국 운영체제 위에서 프로세스가 되고, CPU와 메모리 자원을 할당받아 실행된다.

따라서 운영체제 개념은 단순한 CS 이론이 아니라, 프로그램이 실제로 어떻게 동작하는지 이해하기 위한 기본기라고 볼 수 있다.
